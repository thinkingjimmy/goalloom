# Billing acceptance and development tools

INPUT: Explicit development-only credentials and disposable test identities.
OUTPUT: Repeatable backend and provider evidence under `output/tests/billing/desktop/`.
POS: Manual D0–D3 tooling; no production mutation, live charge, model request or packaged-desktop acceptance.

[PROTOCOL]: Update this header when making changes, then check README.md.

Read [the billing contract](../../docs/features/billing.md) before changing these tools. Its failure cases were recorded before implementation. Provider connectivity and controlled fixture acceptance must be reported separately. Cleanup failures retain finite network cause codes and known source locations; a saved deletion intent alone never proves absence. `.env.billing.local` must be owner-only and ignored; never print secrets or raw provider payloads.
