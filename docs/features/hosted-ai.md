Responses use `Cache-Control: no-store`. Results live only in the original request memory. ## Failure cases fixed before implementation

| Scenario | Expected observation |
|---|---|
| Missing/forged/expired/wrong-project session; client user/model/URL injection | Rejected before provider admission; no charge attributed to another account |
| Concurrent devices reserve the last budget; duplicate POST/GET across accounts | One atomic winner; action reused, no extra provider call; cross-account reads fail |
| Timeout, disconnect, malformed provider output, absent usage, late receipt | Reservation retained, bounded reconciliation, one settlement; no task write or automatic retry |
| Original response is lost, worker terminates, or an old receipt is cleaned up | No result recovery; original cost retained; no automatic rerun or renewed ID |
| AI login without sync configuration; cancel; A → B → A; token expiry | No sync RPC; no inherited consent; A restores only A settings; stale work cancelled |
| Enter before response; manual edit/undo; feature switch; reset/reload | Existing saved task retained; stale result cannot write/cache or clear a newer session |
| Logged-in onboarding; local onboarding; cancelled/late login | Actual two/three-step progress; explicit calendar confirmation; no automatic AI consent/call |
| Statistics missing rows/costs, denied access, UTC boundaries, environment filter | Read-only, redacted, repeatable totals; incomplete is never confirmed zero |
