## 2. 目标与非目标

**目标**

- G1 年、半年两个时间列，与现有时间列能力一致：列内新建与按周期草稿、拖动排序、右键顺延、前后周期浏览、往期页、详情、搜索定位、关联 / 流程 / 关系线、撒花。
- G2 两种日历模式：365 天（默认）与自然年。
- G3 Onboarding 第一步选择模式，默认 365 天；方向放进年列。
- G4 现有工作区、备份与 JSON 导出可以通过手动导入无损进入新版，默认视为 365 天模式。
- G5 Jev 能识别并推测「这一年 / 这半年」的执行时间；流程洞察的断点、空列卡、AI 拆解覆盖年 → 今天六级。

**非目标（本期不做）**

- 设置完成后修改模式或起点：仍需备份并重置，与现有日历锁一致（AGENTS.md 已把「设置后修改日历」列为后续可选项）。
- 年 / 半年复盘（复盘仍只有周、月及合并）。年 / 半年 / 3个月自动顺延已于 2026-10-05 纳入范围，默认仍手动。
- 时间列显隐已由 2026-10-04 的[独立需求](column-visibility.md)接续；本规格不重复其规则。
- 关联的进度汇总或状态联动（D06 不变）。
- 官网与 README 的定位文案（目前是「把三个月的方向，连接到今天的行动」），另起网站任务。

## 3. 定义

### 3.1 尺度与边界

| 尺度 | key | 365 天模式（起点 A） | 自然年模式 |
| --- | --- | --- | --- |
| 年 | `year`（新增） | 从 A 起每 12 个日历月 | 1/1–12/31 |
| 半年 | `half`（新增） | 从 A 起每 6 个日历月 | 1/1–6/30、7/1–12/31 |
| 3个月 | `cycle`（沿用 key） | 从 A 起每 3 个日历月（即现状） | 自然季度 |
| 本月 | `month` | 自然月 | 自然月 |
| 本周 | `week` | 按所设周起始 | 同左 |
| 今天 | `day` | 自然日 | 同左 |

规则：

- 三个锚定尺度（年、半年、3个月）都从**原始起点**推导，第 n 个边界为 `A.add({ months: n × 步长 })`；月底截断但不逐轮漂移。
- 边界都是「A + 3 的倍数个月」，所以**年边界 ⊂ 半年边界 ⊂ 3个月边界**，三层天然嵌套。月 / 周 / 日与 365 天模式下的锚定尺度不保证对齐，现状就是如此。
- 自然年模式 = 起点固定为确认当年的 1 月 1 日，不另写一套算法。
- 起点不得晚于工作区今天；早于起点的年 / 半年 / 3个月不存在，往前浏览止于起点（与现在的 3个月 相同）。
- 周期 ID 规则不变，新尺度形如 `…:year:2026-10-02`、`…:half:2026-10-02`。

### 3.2 示例（用项目锁定的 Electron 原生 Temporal 实算）

| 场景（今天 2026-10-02） | 年 | 半年 | 3个月 |
| --- | --- | --- | --- |
| 365 天，起点 = 今天 | 2026-10-02 → 2027-10-01（365 天） | → 2027-04-01（182 天） | → 2027-01-01（92 天） |
| 365 天，起点 = 2026-09-23 | 2026-09-23 → 2027-09-22（剩 356 天） | → 2027-03-22（剩 172 天） | → 2026-12-22（剩 82 天） |
| 自然年 | 2026-01-01 → 12-31（**剩 91 天**） | 07-01 → 12-31（剩 91 天） | 10-01 → 12-31（剩 91 天） |

边界样例：起点 1/31 的 3个月边界依次为 1/31、4/30、7/31、10/31（不漂移）；起点 2028-02-29 的年边界依次为 2029-02-28、2030-02-28、2031-02-28、2032-02-29。

### 3.3 「365 天」的含义（D2）

按「12 个日历月」：每年都从同月同日开始，闰年那一年有 366 天。不采用严格 365 天滚动，因为那样起点会在闰日之后提前一天（2026-10-02 → 2027-10-02 → 2028-10-01），列头日期每隔几年就变一次。界面继续叫「365 天」，说明文字写「从起点日起，每 12 个月为一年」。

## 4. 产品规则

### 4.1 年 / 半年列

- 顺序固定：Later（侧栏）｜ 年 ｜ 半年 ｜ 3个月 ｜ 本月 ｜ 本周 ｜ 今天。
- 与现有时间列一致：列头 B 周期切换器（标题即按钮，←/→ 逐期，↓ 打开面板，Esc 回本期）、列内新建与按周期保留草稿、拖动排序、右键「移到下一年 / 下个半年」与「移到…」子菜单、往期页（编辑、补勾、重开、删除 / 还原、移动）、详情显示真实周期、搜索与定位。
- 周期面板：年、半年与 3个月 一样用列表（最多含本期之前两期，其余向未来补齐，共 6 项）。
- 关联：上级必须在严格更长的列，链条变为 年 > 半年 > 3个月 > 本月 > 本周 > 今天，规则本身不变。**年列成为最长列**，原来针对 3个月 的三条特殊规则移到年列：「关联到上级」置灰、不能从该列发起拖拽关联、单流程筛选时默认隐藏该列待办的流程圆点。
- 到期未完成：六尺度均可选择手动／自动；年、半年与 3个月默认手动。开启自动后只处理从开启当期开始的来源周期，更早积压仍在往期手动安排。
- 撒花：设置 › 看板的逐列开关增加年、半年，默认开启（同 3个月）。
- 自动排序：年列（最长列）和 Later 不参与；半年、3个月、本月、本周、今天跟随最近一级上级排列。3个月 原来不自动排序，现在有了更长的上级，也会参与。关闭自动排序时，这五列显示中的排列都要保存下来（BUG-10）。
- 列宽与显示：六个时间列默认显示；显隐与按可见列数等分见[列显隐规格](column-visibility.md)。最小 320px，放不下时只在时间区出现横向滚动条。列内新建、明确定位、往期返回等需要聚焦某列时，把该列横向滚入视口；拖动沿用右缘自动滚动。

### 4.2 日历模式

- 首次配置时选择，默认 365 天；与时区、周起始、起点一起在「确认并开始」时锁定。
- 365 天：起点默认确认当天（工作区时区）；「更改起点」可选本月 1 日或不晚于今天的自选日期（D3）。
- 自然年：起点固定为当年 1 月 1 日，无需选择。
- 设置 › 日历与顺延只读显示模式、起点、时区与周起始，并标明「已锁定」（版式见 §4.5）。修改需备份并重置；重置后重新进入向导，可以重新选择。
- 导入 / 恢复的数据集自带模式；v1–v5 数据集一律视为 365 天，起点 = 原 `cycleAnchor`。

### 4.3 命名与年份显示（D8）

列名与相对名（文案建议，实现时五语言同步）：

| 位置 | 365 天模式 | 自然年模式 |
| --- | --- | --- |
| 列标题（本期） | 1年 · 半年 · 3个月 | 今年 · 半年 · 本季度 |
| 上一期 / 下一期 | 上一年 / 下一年、上个半年 / 下个半年、上个 3个月 / 下个 3个月 | 去年 / 明年、上个半年 / 下个半年、上季度 / 下季度 |
| 返回本期按钮 | 回到当期（三列共用） | 回到今年、回到当期、回到本季度 |
| 右键首项 | 移到下一年 / 移到下个半年 / 移到下个 3个月 | 移到明年 / 移到下个半年 / 移到下季度 |

年份显示规则：**只在可能有歧义时显示年份。**

1. **有相对名就不带年份。** 本期、上一期、下一期的列头用列名或相对名，旁边的日期不带年份。年 / 半年的相邻期也用相对名作列头，不沿用 3个月「非本期直接用日期作标题」的做法，因为年 / 半年的日期每年都重复。自然年的年列只显示「今年 / 去年 / 明年」，不另写日期。
2. **没有相对名时，把不带年份的日期视为「今年」。** 适用于两期以外的列头和周期面板的列表行：日期哪一端不在今年，就只给那一端加两位年份；两端落在同一个其他年份时，只在开头加一次。
3. **自然年的年列以年份命名**，更远的期直接写「2028」；季度、半年不在今年时写「2027 Q1」「2027年1月–6月」。
4. 悬停始终显示带年份的完整日期（现状不变）。

示例（今天 2026-10-02；365 天模式的起点设为 2025-10-02，以便出现往期；日期按中文格式，其他语言沿用 Intl 短日期）：

| 场景 | 显示 |
| --- | --- |
| 年列：本期 / 上一期 / 下一期 | 1年 · 10/2 – 10/1；上一年 · 10/2 – 10/1；下一年 · 10/2 – 10/1 |
| 年列：两期之后 | 28/10/2 – 29/10/1 |
| 半年列：本期 / 下一期 | 半年 · 10/2 – 4/1；下个半年 · 4/2 – 10/1 |
| 半年面板六行 | 25/10/2 – 4/1 · 4/2 – 10/1 · 10/2 – 27/4/1 · 27/4/2 – 10/1 · 27/10/2 – 28/4/1 · 28/4/2 – 10/1 |
| 自然年：年列 | 今年；明年；更远写 2028 |
| 自然年：半年 / 季度 | 半年 · 7月–12月；下个半年 · 1月–6月；本季度 · Q4；下季度 · Q1；两期以外、今年内写 Q2，不在今年写 2027 Q2 |

- 365 天模式的 3个月 列头、以及月 / 周 / 日列保持现有规则。3个月 面板列表改用规则 2，顺带修正 BUG-09（同名行）。规则 2 以后也可以推广到其他列的远期列头（现在一律不带年份），本期不做。
- 建议把原来 3个月 的「上个周期 / 下个周期 / 本周期」改为「上个 3个月 / 下个 3个月 / 本期」：有了年和半年之后，「周期」一词有歧义。这会改动现有文案和测试断言。
- 所有新文案覆盖中、英、日、西、法；Jev 与洞察提示词仍只用中文。

### 4.4 Onboarding（三步，D9 已确认）

进度条三步：日历 · 方向 · AI 助手（可选）。

1. **日历**（新的第一步，选择模式）
   - 标题问「你的一年，从哪天开始？」，下方一句说明：日历决定 1年、半年和 3个月从哪天起算，月 / 周 / 日始终按自然日历。
   - 两张卡片组成单选组（方向键切换），默认选中并聚焦「365 天」（带「默认」标记）。每张卡片实时显示真实日期，并用同一条时间轴画出当前这一年：四段 3个月、两个半年之间留出更宽的间隔，已过去的部分着色，标出「今天」。两种模式的差别因此一眼可见（365 天从今天起是完整的一年；自然年在 10 月只剩约四分之一）：
     - 365 天：「1年到 2027/10/1 · 半年到 4/1 · 3个月到 1/1」
     - 自然年：「今年还剩 91 天 · 本季度到 12/31」
   - 卡片下方一句话保留时区、每周开始两个胶囊：「日期按 [时区] 计算，每周从 [星期一] 开始。」，它们会影响卡片里的日期。
   - 选中 365 天时，卡片底部有一行「起点 今天 · 10月2日 ⋯ 更改起点」；展开后在同一行选择今天（默认）/ 本月 1 日 / 自选日期（不晚于今天）。
   - 底部说明行（锁图标）注明「日历确认后不能直接修改；要重新配置，需先备份并重置工作区」。主按钮「下一步」（Enter 同义），此时还不锁定。
2. **方向**（合并原来的「方向」和「日历确认」）
   - 标题随模式变化：365 天「接下来这一年，你最想推进哪件事？」；自然年「今年，你最想推进哪件事？」并显示剩余天数。示例改为一年尺度（如「跑完一场全程马拉松」「读完 24 本书」「换到理想的工作」，最终文案实现时定），可点示例或留空。进入本步时聚焦输入框。
   - 输入区下方的锁图标与两行摘要（与按钮同一行，固定在底部，不画底栏样式）：第一行「将锁定：365 天 · 起点 10月2日 · Asia/Shanghai · 周一开始」及「修改」（回到第一步，草稿保留）；第二行「日历确认后不能直接修改；要重新配置，需先备份并重置工作区」。
   - 在输入框按 Enter 不会直接锁定，只把焦点移到「确认并开始」；再按 Enter 或点击才确认。锁定不可撤销，必须显式确认。
   - 按钮「上一步」「确认并开始」。确认即锁定日历；方向非空时作为普通、可撤销的流程根创建在年列；方向创建失败不回滚日历（现状）。
   - 起点由确认事务按工作区今天解析。如果界面上显示的日期已经过时（例如停在这一步跨过了午夜），确认会被拒绝并提示「日期已变化，请确认新的起点」，什么都不锁定；界面刷新后草稿保留，用户再确认一次（§6.2、BUG-12）。
   - 年列当期剩余不足 14 天时（自然年模式在 12 月下旬，或 365 天模式选了较早的自选起点），方向默认放进下一年；标题下的剩余天数行改为「这一年只剩 9 天，方向会放进下一年（2027年1月1日 起）· 改回今年」，不另设提示框。
3. **AI 助手（可选）**：不变。

**向导结束后的看板**：如果方向写进了下一年，进入看板时年列直接打开到那一年，方向行高亮（沿用搜索的「定位」），列头显示「明年」和「回到今年」；半年列同步打开到与它同一天开始的半年，并出现为它拆解的空列卡（§4.7）。这两列的选择只在本次会话内保持，重启后回到当期，之后可以从年列切到明年或用搜索定位。

其他：
- 步骤之间草稿保留；切换语言保留草稿；IME 组合输入不提交（现状）；重置后重新进入向导，模式恢复默认 365 天。
- 停留在向导里时，到了所选时区的午夜、窗口重新获得焦点或从睡眠唤醒，都要重新计算今天，并一起刷新卡片日期、剩余天数与提示行，以及方向的目标周期（本年还是下一年）。

### 4.5 设置

2026-10-05 负责人更新顺延规则：六个尺度均可独立选择手动／自动，顺序固定为年 → 半年 → 3个月 → 本月 → 本周 → 今天。只有今天默认自动，其余默认手动；开启自动从当前源周期生效，不追溯更早积压。此规则替代下文历史方案中「年／半年无策略、3个月始终手动」的约束。

Implementation failure cases to cover before changing production code:

- Settings must render six editable rows in horizon order, retain choices after restart and show translated mode descriptions in every locale.
- Manual policies must leave expired items in place; automatic policies must move eligible items once at the correct rolling/natural boundary, including month-end clamping and leap years.
- Enabling or re-enabling automatic rollover must not sweep older backlog, future items, completed/cancelled/archived/deleted items or Later.
- Stale policy versions must fail without writes; rollover must preserve text, dates and relationships, and batch undo must restore positions with current-period holds.
- Current JSON/SQLite exports must round-trip all six policies; v1–v6 sources must retain their four policies and business history while receiving manual year/half defaults. Missing/duplicate/mismatched policies must still fail validation.
- Schema v7 must refuse older workspace files without modifying them, retaining the existing explicit export/import upgrade workflow.

- 日历与顺延 › 日历设置是一张只读卡片，自上而下：
  - 概要：模式名（365 天 / 自然年）、起点说明（「从 2026年9月23日 起，每 12 个月为一年」或「按 1 月 1 日起的日历年安排」）、「Asia/Shanghai（GMT+8）· 每周从星期一开始」，右侧「已锁定」标记。
  - 本年度：当前一年的起止日期与剩余天数，下面是与向导相同的时间轴；再下面三项「下一年度开始 / 下个半年开始 / 下个 3个月开始」（自然年为「下季度开始」），日期等于当期年 / 半年 / 3个月的结束日。
  - 「更换日历」行：说明模式和起点已锁定，要更换需先备份、再重置工作区，重置会清空全部条目、主题和备份保留；右侧标出目的地「备份与恢复 ›」。点击后进入「备份与恢复」，把重置入口滚入视口并聚焦，卡片短暂描红一次；从导航进入该页时不标记。它取代原来放在分组标题旁、看不出后果和去向的「前往重置」按钮。
- 到期未完成：按年 → 半年 → 3个月 → 本月 → 本周 → 今天排序，六行使用同一手动／自动顺延控件，说明跟随当前模式变化；仅今天默认自动。列名按最长名称对齐，五语言均使用相同布局。
- 看板：撒花开关增加年、半年。
- 恢复 / 导入预览：来源日历一行显示模式。

### 4.6 智能输入（Jev）

- 执行时间（原文写明）选项增加：`year`「这一年内要做」、`half`「这半年内要做」。`future` 仍只表示原文写的是今天之后才开始的周期（明天、下周、下个月、明年、下个半年……）。被判为 `future` 的事项会放进 Later 并提示，所以「下半年」这类说法不能一律算作未来。
- 口语周期按模式和今天判断：

  | 原文 | 自然年模式 | 365 天模式 |
  | --- | --- | --- |
  | 今年 / 这一年 / 年内 | 年列本期 | 年列本期（滚动的一年，预览显示实际日期） |
  | 这半年 / 半年内 | 半年列本期 | 半年列本期 |
  | 上半年 / 下半年（不带年份，指今年） | 正在进行的那一个 → 半年列本期（例：10 月说「下半年完成」）；还没开始的 → `future`（例：3 月说「下半年完成」）；已经过去的 → `unclear` | 先换算成自然半年的日期：从今天到它结束这一段落在半年列本期内 → 半年列；否则落在年列本期内 → 年列；还没开始 → `future`；已经过去 → `unclear` |
  | 下个半年 / 下一个半年 / 明年 / 明年上半年 | `future` | `future` |

- 实现：新增一个只处理中文的纯函数，按模式、起点和今天把上表里的说法解析成「对应选项 + 实际日期」，写进 `state` 作为提示，执行时间题的说明要求优先采用。这个函数用单测覆盖两种模式，以及 6/30、7/1、12/31、1/1 这些边界日期。
- 推测选项（原文没写执行时间时）增加：`year`「适合在这一年内推进（需要长期投入的大目标）」、`half`「适合在半年内推进」。原文写明的执行时间始终优先，推测仍只对没写时间的片段生效、标「推测」。
- `state.periods` 增加年、半年的实际日期，Jev 按实际日期判断，预览展示实际范围，用户可以改（见 R12）。
- Composer「调整 · 列」菜单变为 今天=1 … 3个月=4、半年=5、年=6、Later=7。
- 接受「可能的上级」建议时，仍按「上级之下最长的合法列」移动：上级在年列时移到半年。
- 评测：现有评测器证明不了「两种模式 + 推测」。它让所有用例共用 2026-09-23 和一组固定周期，只断言原文写明的执行时间，推测结果只写进报告。需要先改评测器：
  - 每个用例可以指定自己的日历（模式、起点、今天、时区、周起始），周期用产品的 `currentPeriod` 现算；不指定时沿用现有的固定上下文，原有 50 条样例不受影响。
  - 新增对推测执行时间（`inferredHorizon`）的断言，包括值和是否确定。
  - 补对照样例：同一句「下半年完成」在自然年 10 月 → 半年列、3 月 → `future`，365 天模式按上表换算；「下个半年」→ `future`；年 / 半年的写明与推测；年 / 半年的上级候选。
  - 改完后经负责人授权，用真实模型连续跑三次全量 `pnpm eval:smart`，三次都要全部通过。

### 4.7 流程洞察

- 链条扩为 年 → 半年 → 3个月 → 本月 → 本周 → 今天。
- 断点「＋」：流程里当期、未完成且没有任何当期下级的条目，提示补下一级（年 → 半年、半年 → 3个月……），沿用「只问最近缺失的一级」。
- 跳级（补里程碑）：只保留「今天直接挂在本月下、跳过本周」这一种；年 → 3个月、半年 → 本月这类跳级是正常用法，不提示。
- 空列卡：半年、3个月、本月、本周、今天都可以出现。建议来源只取上一列中**还没有任何当期下级**的未完成条目，否则跳过半年的用户（年直接挂 3个月）会一直看到「半年还是空的」（见 R7）。
- AI 拆解与起草：目标列增加半年、3个月；提示词补充颗粒度规则（如「半年 = 半年内可验收的阶段成果；3个月 = 一个季度内可交付的里程碑」）。
- 未来周期（主要服务于「年底方向放进明年」，§4.4）：
  - 年、半年列显示未来周期时，也提供右键「拆解」，下级是半年 / 3个月。
  - 半年、3个月 列显示的未来周期落在左侧一列所显示的周期之内时，也会出现空列卡。
  - 拆解出的下级放进「与上级同一天开始」的那一期。年、半年、3个月 的边界层层嵌套，这一期必然存在。
  - 月 / 周 / 日的未来周期维持现状：不出空列卡，也不提供 AI 拆解。断点「＋」仍只看当期。
- 复盘仍是周 / 月 / 合并；复盘总览的流程 × 列矩阵增加年、半年两列。
- 需要用真实模型复核起草质量（`pnpm test:insight-live`）。

### 4.8 兼容与升级

- 不做原地升级（D10）：新版遇到旧版本的工作区文件时拒绝打开，提示「不支持的工作区版本，原文件未修改」，并给出工作区与备份目录的位置；不写入、不建副本。
- 升级方式：负责人按 §6.3 的步骤，在旧版导出完整 JSON，移走旧数据库文件，在新版里「从文件恢复」。已有周期、位置、事件、回执全部原样导入；现有日历读出来就是 365 天、起点 = 原 `cycleAnchor`。
- 导入走的是整库恢复：恢复后自动顺延会暂停、等你确认；工作区代次更换，会话撤销记录清空。
- 新版仍能读取 v1–v6 的 JSON、`.sqlite` 文件和旧备份，保留原有四条策略，并补充年／半年手动策略；补充策略从导入当天的当期生效。
- 当前工作区为 v7；旧版本无法打开 v7 工作区（沿用现有「版本较新」提示），v7 的备份／导出也不能在旧版本恢复。

## 5. 体验问题与对策

**R1 七栏放不下（六列默认显示；显隐需求已接续 D4）**

- 计算：Later 332px + 时间区内边距 16px + 6 × 320px ≈ **2268px**（现在 4 列也要 1628px）。常见宽度：13 寸 MacBook Air 1470pt、14 寸 Pro 1512pt、16 寸 Pro 1728pt、1080p 外接屏 1920px。
- 后果：14 寸全屏展开 Later 时只看得到年、半年、3个月和半个本月；收起 Later 也只到本周的一部分，「今天」列在屏幕外。只有收起 Later 且宽度 ≥ 1936px、或展开 Later 且宽度 ≥ 2268px 时才能一屏看全。
- 本期对策：需要聚焦某列的操作（列内新建、明确定位、往期返回）都把目标列滚入视口；拖动沿用右缘自动滚动；横向滚动条只覆盖时间区。额外的列选择能力由[列显隐需求](column-visibility.md)定义。
- 后续可选（不在本期）：在本机记住时间区的横向滚动位置，或提供「跳到今天」的快捷方式。

**R2 「365 天」与闰年**：已按 D2 采用 12 个日历月，见 §3.3。

**R3 365 天模式下月与锚定尺度不对齐**：例如 3个月 10/2–1/1 横跨 4 个自然月。这是现状，已按 D1 保持自然月；需要对齐的人可以把起点改为本月 1 日。

**R4 当期所剩无几**：自然年模式中途开始时，年、半年、季度可能同一天结束（10 月开始时三列都到 12/31；12/28 开始则都只剩 4 天）。方向放进年列后（D6），12 月下旬设置的方向几天后就会变成往期积压。对策（D9 已确认）：第一步卡片显示剩余天数；方向步骤在年列当期剩余不足 14 天时，默认放进下一年。只写进未来周期还不够：看板默认只显示当期，空列卡也只看当期上级，用户进入看板会看不到这个方向。因此向导结束时要把年列、半年列打开到对应的未来周期，未来周期也要能拆解（§4.4、§4.7）。

**R5 年 / 半年日期每年重复**：365 天模式下每一年的月日都是 `10/2 – 10/1`，半年也只有两种月日。已按 D8 采用「只在可能有歧义时显示年份」：相邻期靠相对名区分，远期和面板列表按规则 2 补年份（§4.3）。

**R6 Onboarding 预览太挤**：现在预览是 5 等分网格，7 栏后每栏只有约 1/7 宽。已确认改成「列头条」，只在年列展开一行「待确认」（§4.4）。2026-10-03 负责人进一步决定去掉该预览：方向步骤只保留输入与说明。

**R7 层级变深**：6 级规划容易让人觉得每一级都得填，空列卡也会层层出现。关联本来就允许跨级（年可以直接挂本月），任何地方都不强制逐级；空列卡建议只为「还没有任何当期下级」的上级出现（§4.7）。这条规则也会作用于现有的本月 / 本周 / 今天空列卡：上一列条目已经有更短的下级时，空列卡不再出现。

**R8 Composer 列快捷键变化**：调整菜单现在是 今天=1 … 3个月=4、Later=5；加入后变成 半年=5、年=6、Later=7。Later 的键位会变，需要写进更新说明。

**R9 首次引导链路（D6 + D7）**：方向在年列后，首次进入看板的引导变为半年列的空列卡「半年还是空的 · 起草下一步」；AI 起草半年目标的质量需要真实模型复核。若洞察的 AI 服务未连接，空列卡仍提供「自己写」，并与列头 ＋ 一样打开行内新建。年底方向放进明年时，引导改为在半年列显示明年第一个半年的空列卡。

**R10 模式不可改**：第一步卡片下方和确认摘要都写清楚；设置页只读展示，并指向「重置」。

**R11 回归面大**：约 20 个桌面脚本 / 夹具通过向导 UI 初始化，向导改版会全部受影响；测试窗口大多在 1280–1880px，默认 6 列时都会横向滚动，跨列拖放用例需要先把源 / 目标列滚入视口，不要依赖超出屏幕的窗口尺寸（macOS 可能限制窗口不超过屏幕）。建议先抽一个共享的「完成向导」测试助手。

**R12 「今年 / 下半年」的口语与滚动周期不一致**：365 天模式下用户说「今年」通常指自然年，而年列是从起点滚动的一年；「下半年」在两种模式里含义也不同。如果把「下半年」一律当成未来周期，自然年模式 10 月说的「下半年完成」会被错放进 Later。对策：按 §4.6 的表格，由代码按模式和今天先解析成选项与实际日期再交给 Jev；预览始终展示实际范围；评测加入对照样例。

**R13 停在向导里跨过午夜**：现有向导把渲染时算出的日期提交为起点，服务端只检查不晚于今天。停在这一步跨过午夜再确认，会把昨天永久锁成起点（BUG-12，现在就存在）。对策：确认事务按工作区今天解析起点，与界面显示不一致就拒绝；向导在日期变化时主动刷新（§4.4、§6.2）。

## 6. 工程方案

### 6.1 领域（`src/domain`）

- `calendar.ts`：`Horizon` 增加 `'year' | 'half'`；`Calendar` 增加 `mode?: 'rolling' | 'natural'`；`cycleRange` 泛化为按 3 / 6 / 12 个月计算的锚定区间；`currentPeriod` 支持年 / 半年；`precedingPeriod` 对三个锚定尺度在起点处都返回 null；`validateCalendar` 要求自然年模式的起点为 `YYYY-01-01`。
- `relations.ts`：逻辑不变（依赖 `horizons` 顺序），补测试。
- `parent-order.ts`：`rank` 增加年 / 半年（或改为从 `horizons` 推导）。之后 `parentOrderedHorizon`（`rank > 0`）会把半年、3个月 也纳入自动排序；保存排列的 SQL 必须用同一个判断（§6.4、BUG-10）。
- `rollover.ts`：沿用通用候选与撤销 hold 规则；年／半年／3个月开启自动后也按所锁定日历的实际边界顺延。
- `import-validation.ts`：按来源版本校验策略，v1–v6 必须有原四条且 cycle 手动，v7 必须有完整六条；周期边界按数据集日历复核。来源校验不改历史，新增默认策略仅在替换事务中写入目标库。

- 导入走整库恢复：恢复后需要点一次「确认按设置处理」才会恢复自动顺延；会话撤销记录会清空。
- 注意一：如果当初选的是「本月初 / 本季度初 / 自选」，你的「年」会从那一天开始，而不是首次使用那天。
- 注意二：想改成自然年没有无损路径。自然季度和原有 3个月 的边界不同，旧周期在自然年日历下通不过边界校验，只能重置（丢失历史）或做一次改写历史的转换（违反「不改写历史与回执」的约定），不建议。
- 注意三：升级不会移动任何条目，现有流程根留在原来的列（向导方向当初默认放在 3个月）。想把某个流程挂到新的年目标下，需要先把年目标设为流程起点（选一个颜色），再把原流程根关联到它下面；原流程会并入年目标的颜色。

## 9. 潜在 bug（需开发者测试）

下面这些问题 TypeScript 都查不出来：起因是字符串枚举、写死的 SQL、`as` 类型断言或被吞掉的异常。大多数要到快照里出现年 / 半年之后才会在运行时暴露；标「现有」的两条现在就存在。每一条都要先写一个能复现的自动化测试，确认它失败，再修复，最后勾选。

### BUG-01 AI 请求的周期键校验失败（Jev 与洞察）

- [x] 已修复并通过自动化回归验证
- **触发**：`metadata()` 开始返回年 / 半年的当期后，快照的 `periods` 有六个尺度。
- **根因**：`smartPreviewSchema.periods` 是 `z.record(z.enum(['day','week','month','cycle']), …)`，`insightBoardSchema.periods` 是 `z.partialRecord(z.enum([...同上]), …)`。zod 4 遇到多出的键会直接报错（已用项目的 zod 4.6.5 验证）。`main/smart/context.ts` 用 `as SmartContext['periods']` 把全部周期塞进上下文，`preview.ts` 又原样放进预览；`boardDigest` / `reviewDigest` 也直接遍历 `snapshot.periods`。
- **现象**：
  - Jev：主进程能生成预览，但 preload 用 `smartReplySchema` 校验回复时失败，composer 整理报错。
  - 洞察：起草请求（右键拆解、空列卡「起草下一步」、复盘里的下一期规划）和复盘小结请求，都会在主进程 `smartActionSchema.parse` 被拒，界面显示失败。
  - 附带问题：`periodText` 用 `period.horizon as Planned` 取中文名，年 / 半年会得到「undefined（2026-10-02 至 2027-10-01）」这样的文本。
- **测试**：
  - 单测：用含六个周期的快照调用 `boardDigest`、`reviewDigest`，结果必须通过 `insightBoardSchema`，且文本里没有 `undefined`。
  - 单测：用含六个周期的上下文生成预览，必须通过 `smartPreviewSchema` 与 `smartReplySchema`。
  - E2E：看板上有年 / 半年任务时，跑 composer（受控 fixture）以及 `test:insight-generation` 的起草、复盘路径。
- **期望**（D7）：请求成功，Jev 与洞察拿到年 / 半年的实际日期。
- **修复方向**：这些 schema 的键改为从共享的周期尺度常量派生；去掉两处 `as` 断言，让类型检查能发现遗漏。

### BUG-02 洞察的 `shorter()` 对不认识的尺度返回 3个月

- [x] 已修复并通过自动化回归验证
- **根因**：`chain[chain.indexOf(horizon as Planned) + 1]`。`indexOf` 为 -1 时加 1 得 0，取到 `chain[0]`，也就是 `'cycle'`；`as Planned` 让 TypeScript 看不出问题。
- **现状**：`shorter('later')` 现在就返回 `'cycle'`。只是 Later 行没有右键菜单、也不参与断点计算，才一直没表现出来。
- **触发**：链条没有同步扩展，或以后再加新尺度。
- **现象**：年列任务出现指向「3个月」的断点「＋」，右键「拆解」直接生成 3个月 的下级，跳过了半年。
- **测试**：
  - 单测：遍历全部 `horizons`，`shorter(h)` 必须是链条里紧挨着的下一级；`day` 与 `later` 返回 null。
  - E2E：没有下级的年目标显示「＋ 半年」，拆解的目标列是半年。
- **修复方向**：未知尺度显式返回 null（或改为显式映射表），去掉断言。
