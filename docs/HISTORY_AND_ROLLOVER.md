# Goalloom · 历史记录与未完成事项处理

v0.3.1 · 2026-09-21。用户已批准产品方向；下列数据边界、设置生效与冲突规则为实施细化，不代表已有代码或测试通过。

**原则：翻页负责看过去，顺延负责安排现在；任务只有一份，过去的计划不能被抹去。**

本文为历史与顺延的详细产品口径。实现模型见 [技术架构](ARCHITECTURE.md)，验证见 [验收用例 C / F / G](ACCEPTANCE.md)。

## 1. 三个概念分开

| 概念 | 回答的问题 | 是否产生新的任务 |
| --- | --- | --- |
| 当前主位置 | 这件事现在安排在哪个时间尺度 / 周期？ | 否，每个任务唯一 |
| 历史计划记录 | 过去曾安排在哪里，当时是什么状态，后来去了哪里？ | 否，只读引用 |
| 任务活动记录 | 哪次操作改变了安排、状态或可见性？ | 否，关键事件 |

“9月历史里能看见，10月当前列也能看见”不等于两个主位置。历史引用没有独立完成开关，不参与当前待办总数，也不能作为可拖动的任务副本。

本需求不新增 OKR 进度，不进行父子任务状态传播，不加入完整内容版本恢复。

## 2. 按列翻页

### 2.1 入口

Later 无时间翻页。其余四列标题区有前后箭头、明确周期标签及回到当前按钮。

| 模式 | 本月列标题示意 | 行为 |
| --- | --- | --- |
| 当前 | 本月 · 2026年10月 | 正常工作；无多余“历史”标记 |
| 过去 | ‹ 2026年9月 · 历史 › / 回到本月 | 只读浏览，右箭头最多前进到当前 |
| 空的过去周期 | 2026年8月 · 历史 | 显示“此周期没有计划记录”，不写入假历史 |

翻页仅改变所操作列的 viewPeriod，不改变任何 placement、完成状态、关联或其他列的视图。P0 不提供向未来翻页创建计划，也不提供回填过去计划；未来排期属于 P1。

日 / 周 / 月按真实日历顺序翻页，可展示中间空周期。三个月列按已经定义的自定义周期序列回看，不为锚点之前虚构周期。首次可追溯边界之前显示“无可用历史”并停止继续回看。

### 2.2 历史模式的操作边界

历史行无可直接操作的 checkbox、添加入口或拖拽手柄，也不是其他列的落点。点击打开“当前任务”抽屉，提示当前位置和当前状态；编辑或完成影响现在，生成新的真实事件，不改写过去。

已删除的任务展示删除状态与恢复入口；不因历史页访问而自动恢复。归档条目仍可查历史。

历史标题 / 说明 / 关联采用当前信息时，页面说明“计划与状态按历史记录展示，内容为当前信息”。仅支持关键状态回看，不承诺还原当时的全文、配色、顺序和完整目标图。

当前关联连线不接到历史行。可以在仍处当前模式的其他列之间显示正常关系；打开历史任务的详情后看到的是它的当前上级 / 下级。

### 2.3 生命周期

一次会话内可保持选中的历史月份；日期变化时，处于当前模式的列跟随日期更新，正在看的历史列不被强行跳走。返回按钮始终指向真实当前周期。

新一次启动默认回到当前工作看板；窗口尺寸、主题可恢复，历史模式不是默认落点。后台周期核对与当前正在看哪一页无关。

## 3. 往期未完成

### 3.1 出现条件

条目状态为待办，未归档、未删除，主位置属于已结束周期，且本轮没有成功自动顺延。按条目唯一主位置的 horizon 投影到对应当前列顶部。显示条件与该列采用手动还是自动策略无关；自动失败、撤销后的本周期抑制、策略生效前积压和恢复后暂停都不能隐藏有效遗留事项。

例如10月的本月列：

```text
往期未完成 · 3                              收起
□ 完成官网设计                      原计划：9月
□ 整理用户反馈                      原计划：9月
□ 发布内测版本                      原计划：8月

[选择事项]     [安排到本月]     [移回 Later]

本月计划 · 2
□ ……
```

这只是对旧 placement 的操作入口，尚未构成10月的新承诺。没有独立遗留任务表，不因检查次数创建更多记录。默认按原计划周期从近到远分组，同周期保留稳定顺序；用户明确排序后保留其结果。

### 3.2 用户操作

支持批量“安排到当前同类周期”和“移回 Later”；单项还可移到其他当前列、完成、取消、打开详情或暂不处理。批量入口只针对所选往期项，不扩展成全产品批量管理系统。

“安排到本月”才改变 period_id 并写手动顺延；移到今天等其他尺度写移动事件。处理后从往期区消失，只保留一份新主位置。

已完成、取消、归档和删除条目不进入往期区。旧周期任务直接完成不会自动进入当前周期计划，其完成记录可在已完成列表按实际日期查到。

不强制弹窗、不锁定看板、不要求延期理由、不逐天补做回顾。区域可折叠但入口和数量不能永久隐藏。

## 4. 设置：未完成事项处理

### 4.1 首版默认值

| 时间尺度 | 默认策略 | 首版允许选择 |
| --- | --- | --- |
| Today / 今天 | 自动顺延到当前日 | 自动、手动 |
| Week / 本周 | 手动安排 | 手动、自动 |
| Month / 本月 | 手动安排 | 手动、自动 |
| Cycle / 3个月 | 手动安排 | 固定手动，仅说明原因 |
| Later | 无 | 不显示策略控件 |

日级维持执行连续性；周、月、三个月保留重新选择方向的机会。设置页说明默认值；不要求首次启动先填完设置才能用。

**帮助文案：** 将未完成事项安排到新的同类周期。不会更改截止日期或目标关联。

### 4.2 自动顺延范围

只处理未完成、未归档、未删除的旧周期条目。不影响任务标题、说明、状态、due_date、关系或其他任务。不因父目标移到新月就同步移动子任务。

每个任务只匹配唯一主位置的策略；月列的目标关联到 Today 任务，不会因此再套用月策略到 Today 任务上。Later 永远不自动分配日期。

延期任务追加在目标列已有未完成事项之后，来源周期按近到远、各周期按稳定原顺序放置；已有当前计划不被重排。已完成分组不参与落点排序。

### 4.3 设置生效，不追溯改计划

启用自动策略时记录“从本当前周期起适用”；不立即搬走更早已积压的事项。设置页显示：**从本周期起适用；已有往期事项需手动安排。**

例：10月15日打开月自动顺延。现有9月遗留仍待手动安排；当前10月计划若到11月仍未完成，则自动顺延。用户明确把9月遗留先安排到10月后，也适用10月以后规则。

关闭自动策略不撤回已成功的顺延；如需恢复，使用对应批次的撤销。再次启用按新的当前周期生效，不清算整份历史。保存策略与生效边界同事务。

若导入旧工作区或没有对应设置，安全默认对已有历史先保留手动处理，新当前周期采用产品默认；在恢复预览中明确展示。

## 5. 成功提示、来源与安全撤销

### 5.1 批次反馈

每次实际自动处理形成一批，例如“已将3项未完成事项从9月顺延到本月”。混合来源使用“已将3项往期事项顺延到本月”，查看面板列明各自来源。

显示查看与撤销；提示只在事务成功后出现。批次记录可在相关任务的活动记录中再次找到，通知暂时消失不等于记录消失。

任务行保留最近一次同尺度顺延的来源标记；详情展示完整关键路径。原计划标记不替代截止日期，也不表示拥有多个主位置。首版不要求显示复杂延期评分或次数排行榜。

### 5.2 撤销

撤销恢复相应条目的原 horizon / period 和可行的原排序位置，保留任务 ID、内容、due_date、关系及状态。排序间隔冲突时按原邻居尽可能插回，不覆盖其他用户排序。

只撤销从原操作后仍未被修改且仍处目标位置的条目；已改名、编辑、移动、完成、删除或又被顺延的条目保守跳过。预览列出可撤销 / 将跳过项，事务内再次检查，提交后报告实际结果。

撤销追加反向记录，不删除原始顺延事件。当前有效顺延次数如在未来展示，要扣除已撤销事件；首版不强制做计数 UI。

已撤销项在撤销执行时该时间尺度的当前周期内进入手动待安排，不再被下一次唤醒 / 重启自动搬回去。抑制状态需落盘。下一周期到来可重新遵循用户策略；用户手动移位则清除旧抑制。界面说明“本周期不再自动顺延此项”。

## 6. 历史展示口径

### 6.1 历史纳入范围

某周期历史显示曾明确安排到该 horizon / period 的条目，按 item ID 去重。来自任务主位置的计划变化，而不是把所有包含在这个月的日任务都当成月计划。

例如 Today 新建且从未放入 Month 的任务，不自动写成“本月计划”；其10月的完成可在全局已完成列表按日期看到。历史页不成为第二套隐式时间视图。

同一周期内离开又返回可显示一条汇总行及详情中的多次移动。首版历史无需还原过去的精确列表顺序。

### 6.2 状态与后续分栏表达

历史页分清“截至周期结束时的状态 / 去向”和“后来发生的事”。后来完成不回写为当期完成；后来重开也不抹除当期曾完成的事件。

| 场景 | 应展示 | 不应展示 |
| --- | --- | --- |
| 9月安排，10月1日顺延，10月4日完成 | 9月：截至期末未完成，后来顺延；10月：来自9月，4日完成 | 9月当月完成 |
| 9月末仍未完，11月才开启应用并顺延 | 9月：截至期末未完成，11月实际顺延；10月无虚假计划事件 | 10月自动顺延过一次 |
| 月计划改为当月某天执行，并在月底前完成 | 月历史：已移至当日执行，注明完成时间；今天仍是唯一主位置 | 再造一个可勾选的月任务 |
| 9月遗留10月直接完成，未改计划位置 | 9月：期末未完，后来10月完成；已完成列表：实际日期 | 自动制造10月主计划归属 |
| 9月完成，10月重新打开 | 9月保留当时完成，另标后来重开；当前任务按最新状态 | 回写9月从未完成 |
| 9月取消 / 归档 / 删除，10月恢复 | 9月保留对应历史状态 / 去向，当前可见性另示 | 用当前状态抹去旧变化 |

全局已完成列表默认展示当前为 done 的条目，按最新一次真实 completed_at 分组；重开后从该列表消失，但旧完成事件仍在历史中。

### 6.3 日历边界

周期为工作区日期区间 `[start_date, end_date_exclusive)`。恰好在结束边界发生的完成属于新日期，不算旧周期内完成。事件记录实际 UTC 时间及写入顺序；历史采用当时固定周期对应的时区边界，不用用户现在的时区重算旧周期。

应用未运行时，仍可从已记录的事件推导那段时间本地状态未发生变化；不得声称创建过未执行的期末快照。数据缺失或只有后补 baseline 时显示“该时段历史不完整 / 无可用历史”，不能用当前完成状态反推。

### 6.4 顺延与移动分类

同一时间尺度从较早周期安排到较晚周期，记为顺延；Today旧日期到新的当天同样适用。Month→Week→Today、移回Later记为移动，不增加延期次数。同周期排序只改排序，不制造顺延事件。

系统只允许自动顺延到当前周期，手动移动也不借历史页回填过去。若经过多个周期但只实际执行一次跨期移动，记一次，记录跨度而不是虚构次数。

## 7. 本地执行、失败与并发

在启动、唤醒、回到前台、日期变化时核对当前周期。无需联网、云服务或应用退出后的系统常驻任务。正在运行时可在下一日历边界唤醒；恢复时始终重新计算，不依赖固定24小时。

先进入统一写入通道，再按实际当前状态与策略决定操作。更新 placement、写事件、写批次与去重结果在同一事务内；失败则全回滚，显示保留原安排的错误，不提前弹成功通知。

重复启动 / 唤醒、多个触发源同时运行、提交已成功但响应丢失，均不得增加第二次移动或第二条重复事件。手动完成与自动顺延竞争时按实际提交顺序串行处理：先完成的条目不再顺延；先顺延再完成则两次真实事件都保留。

每次处理使用同一个观测时间和目标周期，跨边界后下一次核对再处理新周期。用户主动翻页是只读操作，不触发针对“所浏览周期”的顺延。

## 8. 保存、恢复与范围控制

历史事件、策略生效边界、自动批次和撤销抑制字段必须随 JSON 完整导出；关系和任务仍只有一份。事件链仅按技术架构 §4.4 的历史业务字段连续性校验，允许未记事件的编辑造成版本跳号或排序差异；不能要求相邻完整 before / after JSON 全等。导入校验防悬空引用、重复事件、非法状态链、非法日期和未知 schema。恢复前备份，失败不损伤原库。

恢复完成后先展示结果，并暂停本次自动补处理；明确显示“恢复完成，确认后按顺延设置处理往期事项”。用户确认继续后再执行，暂停状态需落盘，防止下次启动绕过确认。

没有历史的旧数据只从迁移 / 导入时建立 baseline，注明历史起点，不复制原 created_at 作为虚假的事件执行时间。已存在的可信历史保持原始时序，不重写为导入时刻。

P0 的事件只覆盖影响计划 / 状态 / 可见性的关键变化。不记录每次按键、hover、滚动或所有文字版本，不建立整套事件溯源应用、目标评分、自动归档 / 删除和完整月报系统。

## 9. 核心验收摘要

- [ ] 翻页不改数据，只改该列视图；历史卡片不能直接完成或拖拽。
- [ ] 默认日自动、周月手动、三个月固定手动；Later无策略。
- [ ] 往期任务可见、可批量安排，不复制ID或丢失关联。
- [ ] 9月→10月→完成仍能分别回答过去状态和后来结果。
- [ ] 顺延不改截止日期、目标关系和其他任务状态。
- [ ] 自动操作可查看并安全撤销，撤销后不立即再次自动搬回。
- [ ] 长时间关闭只记录实际执行，不造中间月份的历史。
- [ ] 事件和当前位置原子保存，重复触发及崩溃重试不重复。
- [ ] 导出恢复保留历史 / 设置；旧数据不伪造过去。

以上均为待实现 / 待执行，不是通过记录。
