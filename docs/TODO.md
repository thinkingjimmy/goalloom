## 1. 工程约束

**结构：** `src/main`（命令 / 存储）、`src/preload`、`src/renderer`、`src/shared/contracts`、`src/domain`（纯业务规则）、`tests`。单实例 / 单工作窗口，一个权威写入通道，不建多框架、同步队列或完整事件溯源。日历区间、候选选择、撤销匹配、历史投影和导入校验放到无 Electron / 数据库 / 全局时钟依赖的纯函数中，显式传入时间、设置和数据；事务服务读取最新状态后再次调用规则并落实数据库约束。纯函数通过不等于持久化 / 并发已验收。

**安全：** renderer → 有限 `window.goalloom` API → contextBridge / preload → 验证后的 main 命令 → SQLite。保持 `contextIsolation=true`、`sandbox=true`、`nodeIntegration=false`、`webSecurity=true`，验证来源 / 参数 / 版本 / DTO；限制导航、新窗口、权限及外链，不暴露原始 IPC、任意路径、SQL 或 shell，日志无正文 / 凭据。生产提供有效 **Content-Security-Policy**：脚本仅本地可信资源，不允许远程脚本、`unsafe-eval` 或任意内联脚本，禁止 object / 非必要网络连接；样式 / 图标按实际组件最小放行，不以关闭 CSP 修复组件。自有协议用响应头，`file://` 路线用及早生效的 meta；开发 HMR 策略与生产分离，测试生产页确实阻断注入。[Electron安全](https://www.electronjs.org/docs/latest/tutorial/security)

**SQLite 选型：** M1 优先评估 `node:sqlite`，通过才锁定；不足再评估 `better-sqlite3`，不同时维护两套驱动。Node 的模块从22.5引入，22.13起免 experimental-sqlite 开关；backup API在22.16 / 23.8加入，不同版本稳定级别仍需核对。Electron历史上也修复过「Node版本够但模块缺失」的问题。必须在选定 Electron 的 main / 受控存储 worker 及两平台安装包中检查 import、API、事务、备份 / 恢复、UTF-8路径，记录 `process.versions.electron/node` 和 SQLite 版本；不以宿主 Node 或「22以上」作保证。内建方案可避免该数据库外部插件的 ABI / rebuild，不消除全部平台风险；DatabaseSync为同步接口，大量查询 / 导入 / 备份应使用受控存储 worker，保留唯一写入权威。[Node API](https://nodejs.org/api/sqlite.html) · [Electron修复记录](https://releases.electronjs.org/pr/47706)

Vite 构建，electron-vite、dnd-kit、测试 runner 均在 M1 验证并锁版；选外部原生驱动时测试 Electron ABI / CPU / rebuild / 打包资源。预览 mock 明示不持久化，正式构建缺存储报错，不放松安全配置。

**图标：** `@hugeicons/react` + `@hugeicons/core-free-icons`，在 `src/renderer/components/icons/` 建轻量共享入口，仅显式导入真实存在的图标。默认 Stroke Rounded、线宽1.5、工具栏20px / 行内16px / 空状态24–32px、`currentColor`。新增 shadcn 检查全部内部图标 / SVG选择器、ref / 焦点 / 键盘 / 命中区，保留许可证；无未授权 Pro、第二套图标库或运行时远程加载。无合适免费图标先用文字。[Hugeicons接入](https://hugeicons.com/docs/integrations/react/quick-start) · [实践](https://hugeicons.com/docs/integrations/react/best-practices)

**代码文档：** 遵循 [AGENTS](../AGENTS.md) 的轻量协议：重要模块边界按需README，复杂模块公开入口注明 INPUT / OUTPUT / POS；源码变化同步契约。800行作为拆分评审信号，不作机械硬上限；不强制每层8文件或每目录README，生成代码 / 素材免模板化注释。不能借维护协议重新堆叠产品规格。

## 2. 数据、日历与写入契约

### 2.1 实体

冻结 D06 / D07 后再定受影响的生产 DDL。保留稳定身份，不预建类型、用户配色、进度、账号或团队字段。

| 实体 | 必要信息 / 约束 |
| --- | --- |
| items | ID、标题 / 多行说明、status、due_date、completed_at、archived_at、deleted_at、version、创建 / 修改时间；无kind / 自定义color。status仅todo/done/cancelled，done才有当前completed_at |
| planning_periods / item_placements | 尺度、日历显示边界、固定start_at / end_at UTC、时区与calendar_rule_id、过渡标记；每项唯一位置 / 排序 / version / auto_hold_period_id。Later周期为空，其余尺度匹配 |
| item_relations | parent / child、失效标记、恢复来源；活跃父子对唯一，同事务防自关联 / 防环。D06单父需活跃child唯一及原子换父，多父则不加该唯一约束 |
| calendar_rules / settings | 版本化时区、week_start、cycle参数；各尺度active / pending规则、effective_at、过渡定义；工作区显示时区、备份启用 / N / 最近结果、rollover_paused_after_restore |
| rollover_policies | 尺度策略、版本、生效源周期；Later无策略，cycle固定manual；跨规则版本用真实周期边界比较，不按随机ID大小比较 |
| operations / item_events | 稳定operation / batch ID、来源、request_hash、结果；event ID、操作内唯一index、全局seq、实际occurred_at、类型、payload版本、有限前后值、undo引用 |
| schema_migrations | 迁移版本 / 执行时间，失败不提升版本 |

软删除保留 item / placement 和事件身份，不物理级联；关系失效须能区分主动解除与删除导致的失效，恢复只尝试本次删除失效的合法边，不能复活先前主动解除的联系。归档不改关系 / status；删除恢复保留原status / archived_at / placement，当前视图按PRD重新过滤。全局已完成 / 已取消包括归档项但排除删除；回收站是所有deleted_at非空条目的专用查询，含Later。

**搜索：** 首版用参数化 `LIKE` 做标题 / 说明字面子串，转义用户输入的 `%`、`_` 和 escape字符，空输入不误展开全库；分页并对快速输入做适当防抖。用10,000条含长中文说明、1字 / 2字 / 中英文混合 / 特殊字符测延迟，不先承诺「一定够快」。暂不上FTS5；trigram是子串方案而非CJK唯一选择，且短于3字符的MATCH有局限；实测不足才评估索引 / tokenizer并保留短词匹配。[LIKE](https://www.sqlite.org/lang_expr.html) · [FTS5](https://www.sqlite.org/fts5.html)

### 2.2 事务、事件与校验

创建条目 / 位置 / 初始关系 / 创建事件同事务；之后当前表、必要事件与操作回执也须全成或全败。operationId同请求重试返回原结果，不同请求冲突；手动命令检查版本，系统在串行写通道重读候选。启用外键、日期 / 枚举 / 唯一约束，前端只预检。

从首笔写入记录创建 / baseline、移动、顺延、状态变化、归档 / 解除、删除 / 恢复及对应撤销。事件只存计划、状态、可见性、版本和必要排序 / hold；标题 / 说明 / 关系编辑可只递增版本。列内排序不伪装成移动或顺延；若需撤销，operations保留受影响项的有限顺序 / 版本回执，不存整列全文快照。所有实际修改递增相关版本；重开清空当前completed_at，旧完成事件保留。

当前看板直接读实体表；历史按明确进入该period的ID去重，取固定结束边界前的业务状态并分开显示后续结果。用item / seq、operation / index、from/to period索引，不重放全库或扫JSON。同时间按seq；边界时刻归下一周期；时钟回拨记录异常、暂停自动时序推断并提示复核，不伪造时刻。baseline以前为unknown，不能由当前状态反推。

**导入链校验与撤销匹配分开：** 业务连续性仅比 horizon、periodId、status、completedAt、archivedAt、deletedAt，并校验每事件类型、身份、日期、seq / 引用 / undo及末尾业务状态与当前表一致。合法未记录编辑可造成版本跳号、排序 / 邻居不同，不能比较整份before/after JSON全等；版本仍须合法不倒退，hold按操作 / 策略验证。撤销则严格匹配当前item / placement版本和原目标位置；导入容许跳号不等于撤销可覆盖后续修改。

### 2.3 日历规则与执行

纯函数以工作区规则计算日 / 周 / 月、固定UTC边界，不用24小时或90天常数。D07若选三日历月，以原锚点+3n月和月末截断计算；周key含起始日期及规则版本。未确认D07时仅做候选fixture，不把公式变成既定迁移。

按PRD保存版本化pending规则及各尺度旧end_at生效点，不覆写现有period或placement；变化取消仅取消pending。每尺度恰有一个当前周期，当前旧规则仍有效直到旧结束边界 B。若新规则边界与B对齐，正常接下一完整周期；否则用 `[B, B之后第一个新边界)` 作为明确标记的过渡周期，再接完整周期。禁止空档 / 重叠；跨时区B可能不是新时区午夜，必须保留真实UTC时刻并在预览显示，不四舍五入后丢时段。D07新锚点允许范围 / 是否开放重设在M0决定，不能允许无界长过渡。设置显示和各列边界使用各自有效规则，历史不重算。

修改设置不移动当前项；原period结束后未完成项才进入往期 / 顺延。来源策略生效范围以固定周期时间和规则谱系验证，hold仍绑定真实当前period。离线后可由已存规则推导区间，不虚构中间任务事件；规则确认时间与实际补处理时间分开保存，JSON包含pending状态。

统一reconcile由启动 / 唤醒 / 前台 / 边界触发，每轮一个observedAt；候选为旧周期有效todo、auto策略、生效范围内、无本目标period hold、无恢复暂停。不能用“今天执行过”跳过新候选。备份检查先于本轮自动修改，失败提示但不伪称任务已丢。

### 2.4 顺延与可撤销操作

按目标周期原子分批、稳定追加排序，写逐项事件与批次回执后通知。手动移动 / 排序 / 完成也保留有限可撤销回执；拖动中只改临时UI，落点后提交，失败保留输入并回滚。排序采用可重排稳定键，反向插入尽量恢复原邻居，不覆盖整列新序列；涉及多项重排的操作须复核受影响集合，不能部分恢复出重复或错乱排序。

撤销使用自己的operationId，在事务中检查原操作未撤销、版本 / 位置匹配；只逆转其负责的状态或位置，不还原正文 / 关系。批次可跳过冲突项并返回实际数量；完整顺序操作有依赖时全组拒绝并说明。逆操作始终引用原operation；原操作有业务事件时另引用相应event并追加反向事件，纯排序撤销只写顺序回执，不伪造移动事件。每个原效果最多成功逆转一次。

若逆转后是旧周期todo，无论原操作为自动顺延、手动移动或完成，都设置撤销执行时该horizon当前period的hold并落盘；当前周期 / Later的普通逆转无需hold。下周期不再匹配，手动移位清除；归档 / 删除 / 当前状态筛选仍优先。原始顺延记录不删除，0项或失败不能报成功。手动完成与自动顺延串行处理，保留真实提交顺序。

### 2.5 备份与完整恢复

日常一致性备份按PRD默认每天首次活跃检查、保留7份；同日成功不重复，失败可重试。SQLite备份API或等价一致性机制覆盖已提交WAL，写唯一临时文件、关闭 / 校验后原子改名，再轮换本应用日常副本；中断 / 磁盘满不删旧副本，不复制活跃主文件冒充完整备份。迁移 / 覆盖恢复前保护副本不参与日常轮换，其备份失败须停止危险操作。设置里的备份恢复复用下述预览 / 校验 / 确认 / 暂停流程，先备份当前工作区，不能盲目覆盖。[SQLite备份](https://www.sqlite.org/backup.html)

JSON带schemaVersion / exportedAt和全部业务实体、规则（含pending）、策略、历史及回执；保留ID / seq / 时序 / 生效边界 / undo / hold。备份文件路径不是可任意写盘指令，外部导入的路径不直接信任。大小限制→schema / 字段 / 日期 / 图 / 链校验→预览确认→保护备份→原子替换→完整性检查。未知schema、重复 / 悬空引用、非法图或真不连续业务链拒绝；失败保留原库。

恢复成功持久化暂停自动补处理，确认才继续；旧数据无事件从真实导入时建baseline，可信历史不改成导入时间。缺旧策略时旧积压先手动、新当前周期用默认并在预览说明。daily副本与逻辑导入校验互补，不能以“已有备份”降低校验；测试真正恢复与历史一致性，不只验证文件存在。
