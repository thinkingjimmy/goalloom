## Retrospective and process correction

The measured local verification took 11m49s and passed first time. Hosted recovery took 34m35s from the first run start (13:16:15Z) to final success (13:50:50Z). Missing provisioning was discovered only after 7m36s; the separate creation attempt failed after another 8m55s because read permission did not grant POST permission. The existing profile was Invalid; its invalidation cause is not established. The late standalone validation duplicated a successful ticket check without the hook's bounded connection-loss recovery. A monolithic package-job retry rebuilt and resubmitted the macOS package. These were avoidable process costs, not evidence of a 34-minute Apple review.

The release workflow now has a lightweight `preflight_only` mode before local full verification, and an obligatory signing/profile preflight before either hosted test job. It uses the existing identity, checks a real signing probe, always removes temporary credentials and keeps a status summary. Profile creation is explicit and limited to preflight; a POST 403 names the operation and directs the operator to regenerate the existing profile before another preflight.

Final `.app` and `.dmg` ticket validation now uses the same three-attempt, single-deadline CloudKit recovery as the notarization hook. Permanent errors and timeouts fail immediately; a native success marker is required. Independent validation saves its own receipts and never resubmits or staples. Upload responses with unknown outcomes are not retried; same-ID status polling remains bounded. Source tests, signatures, Gatekeeper, packaged smokes and publication gates remain intact.

Draft lookup and certificate-extraction commands are fixed in the [release guide](../development.md#托管打包与草稿-release). The 5m26s from hosted success to publication included download/hash/signature checks and orchestration errors; it is not all removable time. New synthetic command fixtures exercise the actual final Bash verification path, not only the hook. Local command acceptance passed: `pnpm --filter @goalloom/desktop exec -- node tests/review/run.mjs package-report notarization session-profile release-workflow` (both package-report fixtures, 32 notarization/final-verification scenarios, 13 profile scenarios and workflow graph contracts). `pnpm typecheck`, Bash/Node syntax and diff checks passed. Existing Vitest ran 45 files: 332 passed and seven loopback callback cases failed inside the filesystem/network sandbox. A separate loopback probe returned EPERM; the affected OAuth file then passed all eight cases outside the sandbox (seven replays plus its already-passing case). Reports: `apps/desktop/output/tests/notarization-fixture/report.json`, `session-profile/report.json`, `release-workflow/report.json` and `release-workflow/oauth-callback.log`. Scope: macOS 26.4.1 / Darwin 25.4.0 arm64, Node 24.21.0; Vitest uses Electron 44.4.4 / SQLite 3.53.4. No product source or native UI changed; full verification, performance and installer acceptance were intentionally not repeated for this process fix. Hosted preflight evidence is recorded separately after execution. No end-to-end speedup is claimed without a future clean release measurement.
