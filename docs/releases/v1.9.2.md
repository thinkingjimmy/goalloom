# Goalloom 1.9.2

## Fixes

- **No macOS Keychain password dialog, including first use.** Starting Goalloom, enabling sync or AI, and restoring saved credentials now use noninteractive Keychain access. Credentials remain protected by system encryption.
- **Saved credentials restore when access is available.** If the keychain is locked or an old credential does not trust the current app, the affected sync or AI feature remains unavailable. The local board stays usable and encrypted credentials are kept. Repair system access outside the app to restore an inaccessible old credential.
- Development builds use separate credentials and a separate default profile, so development and automated tests no longer share the installed app's Keychain item.

## Upgrade

Update from 1.9.0 or 1.9.1 through Settings → About, or install over the existing app. Your workspace and settings stay in place. The workspace format remains v10. macOS downloads are Developer ID signed and notarized by Apple; Windows installers remain unsigned.

**If you still use the published macOS 1.8.0 build, upgrade manually once:** quit Goalloom, open the 1.9.2 DMG, and replace Goalloom in Applications. That old ad-hoc signature cannot authorize the Developer ID update. Your workspace and settings stay in place.

## 修复

- **macOS 首次使用也不再弹出钥匙串密码框。** 启动应用、开启同步或 AI、恢复已有凭据时，都禁止钥匙串授权和解锁弹窗。凭据继续使用系统加密保护。
- **可读取的已有凭据自动恢复。** 如果钥匙串被锁定，或旧凭据不允许当前应用访问，相关同步或 AI 功能会暂时不可用。本地看板继续可用，加密凭据保留。需要在系统中修复访问权限，才能恢复无法读取的旧凭据。
- 开发版使用独立的凭据和默认数据目录，开发与自动化测试不再共用正式安装版的钥匙串条目。

## 升级

1.9.0 或 1.9.1 用户可在「设置 → 关于」更新，或覆盖安装，工作区和设置会保留。工作区格式保持 v10。macOS 安装包已通过 Developer ID 签名和 Apple 公证；Windows 安装包仍未签名。

**仍使用公开版 macOS 1.8.0 时，请手动升级一次：** 退出 Goalloom，打开 1.9.2 的 DMG，把 Goalloom 拖进「应用程序」并替换旧版。旧版的 ad-hoc 签名无法通过内置更新切换到 Developer ID 签名，工作区和设置会保留。
