# Goalloom 1.9.8

## Improvements

- Production sync now uses a separate service from development. Installed Goalloom keeps its existing identity and data location; source development uses its own profile and project.
- Before switching, Goalloom protects the local workspace and preserves tasks, history and calendar. Old account credentials, device authorizations and send journals remain separate from production.
- Google sign-in returns in your app language. Development sign-in focuses the development window without replacing the production app's browser registration.
- Creating a new sync baseline now keeps manually ordered subtasks in their sibling order.
- Verified app backups with inconsistent old sync history can recover validated current data. The preview explains that restoration starts new history; the original backup remains unchanged. External imports keep strict validation.
- The website now provides privacy and terms pages in all five languages.

## Update

Update every computer using sync to 1.9.8. After updating, sign in to Google again. On the computer with your current data, set a sync password to create the production workspace. Use that same account and password on your other updated computers. Versions 1.9.7 and earlier still use the development service and will not receive production changes.

Local data stays available while signed out. Workspace format remains v11. The transition preserves the current board and local history; cloud operation receipts and unresolved differences from the old project do not become production history. Keep the old protective copy until all computers are checked.

macOS downloads are Developer ID signed and notarized by Apple. Windows installers remain unsigned. The published macOS 1.8.0 build requires one manual replacement in Applications.

## 改进

- 正式同步使用独立的生产服务，日常开发继续使用原开发项目。正式应用的身份和数据目录保持不变，开发版使用独立目录。
- 切换前先保护本地工作区，保留任务、历史和日历。旧账号凭据、设备授权和发送记录不会进入新生产项目。
- Google 登录返回页跟随应用语言。开发版直接返回开发窗口，不覆盖正式版的浏览器注册。
- 建立新的同步基线时，保留手动调整的子任务同级顺序。
- 自有备份的旧同步历史不一致时，可恢复已通过校验的当前数据。预览会明确提示恢复后建立新历史，原始备份保持不变；外部导入继续严格校验。
- 官网提供五种语言的隐私政策和服务条款。

## 更新

请将使用同步的电脑均升级到 1.9.8。升级后需重新完成 Google 登录。在保存当前完整数据的电脑上设置同步密码，建立生产空间；其他电脑升级后使用同一账号和密码加入。1.9.7 及更早版本仍连接开发服务，无法收到生产环境的新修改。

退出登录时仍可使用本地数据。工作区格式保持 v11。切换会保留当前看板和本地历史；旧项目的云端操作回执与未处理差异不会成为新生产空间的历史。完成所有电脑的核对前，请保留旧保护副本。

macOS 安装包使用 Developer ID 签名并通过 Apple 公证；Windows 安装包仍未签名。公开版 macOS 1.8.0 需手动替换「应用程序」中的旧版一次。

## Migration acceptance

The owner’s current Mac completed the production transition and encrypted upload. Final comparison preserved current task data and order, active relationships, calendar and original local history. The first upload required controlled repairs from the pre-upgrade backup: restoring missing historical period metadata and correcting one historical completed-task order through a sync arrangement. The published binary does not automate those repairs for another legacy profile. Check another legacy device against its own backup before migration; Windows 11 and two-device acceptance remain manual. New empty profiles do not contain that legacy history. See the [timing and validation record](https://github.com/thinkingjimmy/goalloom/blob/main/docs/releases/v1.9.8-timing.md).

## 迁入验收

负责人的当前 Mac 已完成生产切换及加密上传，最终核对保留了任务数据与顺序、有效关系、日历和原有本地历史。首次上传依据升级前备份做了受控修复：补回缺失的旧周期元数据，并用同步排序操作恢复一组已完成任务的顺序。已发布安装包不会为其他旧工作区自动执行这些修复。另一台旧设备迁移前应依据其备份单独核对；Windows 11 及双机验收仍由负责人完成。新建空工作区没有这些旧历史。详见[耗时与验证记录](https://github.com/thinkingjimmy/goalloom/blob/main/docs/releases/v1.9.8-timing.md)。
