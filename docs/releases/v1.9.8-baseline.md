## 🎯 M2.1 验证结论

### ✅ 容错机制正常工作

**submitWithRetry() 验证：**
- ✅ 首次提交成功（`submitAttempts: 1`）
- ⏸️ 重试逻辑未触发（网络稳定）
- ✅ 代码就绪，待故障场景验证

**waitForCompletion() 验证：**
- ✅ 30 秒轮询间隔精确执行
- ✅ 状态转换正确记录（In Progress → Accepted）
- ✅ 无网络错误，容错未触发
- ✅ 两次轮询后获得最终状态

**Staple/Validate 验证：**
- ✅ 首次成功，无重试
- ✅ 与旧版一致（已有容错保留）

### ⏳ 待验证场景

**需要遇到以下情况才能完全验证 M2.1：**

1. **Submit 阶段网络故障**
   - CloudKit 断线（NSURLErrorDomain -1005）
   - 预期：最多 3 次重试，2s/5s 退避
   - 观察：`submitAttempts` 字段增加

2. **Wait 阶段轮询错误**
   - 单次轮询网络故障
   - 预期：容忍最多 3 次连续错误
   - 观察：`pollErrors` 字段出现

3. **Apple 服务延迟**
   - 公证处理时间超长（>5 分钟）
   - 预期：持续 30s 轮询直到完成
   - 观察：`statusPolls` 数组长度增加

**验证方法：**
- 继续使用 M2.1 代码
- 每次发版下载 `macos-notarization-diagnostics`
- 观察 5-10 次发版数据
- 如遇故障，分析重试日志

## ⚡ M2.3 测试解耦架构验证

### 执行流程（成功路径）

```
test-mac (72s)   ──> package-mac (357s) ──> draft (27s)
test-win (114s)  ──> package-win (183s) ──┘

总时长: max(72, 114) + max(357, 183) + 27 = 498s
```

### Artifact 传递

**上传：**
- Test macOS → `build-mac-arm64` (apps/desktop/out + package.json)
- Test Windows → `build-win-x64` (apps/desktop/out + package.json)
- Retention: 1 天

**下载：**
- Package macOS ← `build-mac-arm64`
- Package Windows ← `build-win-x64`

**开销：**
- Upload: ~4s/job
- Download: ~5s/job
- **总开销：~18s**（相比节省的时间可忽略）

### 失败恢复场景（理论）

**场景 1: 测试失败（已验证）**
```

→ package 不运行
→ 修复代码后完整重跑
→ 反馈时间：~10-15 分钟
```

**场景 2: 公证失败（待验证）**
```
首次运行:
  test-mac (72s) ─✓─> package-mac ─✗─> 公证失败

重跑（仅 package-mac）:
  [复用 artifact] ──> package-mac (357s) ─✓─> 成功

节省: 72s + 25s install = ~97s
```

**场景 3: Windows 打包失败（未遇到）**
