# Goalloom 1.9.9 release timing

Status: Published.

The user request arrival time was not instrumented. Times below are observed UTC. Local verification duration is measured from command preparation to the final log write; it is not a sum of individual test times.

## Local verification

Scope: macOS 26.4.1 / Darwin 25.4.0, Apple M3 Max arm64; physical/VM status was not independently verified. Electron 44.4.4, Node 24.21.0, SQLite 3.53.4. Windows 11 manual acceptance remains separate from hosted packaging.

| Command | Result | Observed seconds | Start UTC | Final log write UTC |
| --- | --- | ---: | --- | --- |
| `pnpm verify` | Interrupted acceptance: pointer-sensitive period-return hint timed out inside `test:insight` | 648.636 | 2026-10-20T01:19:56.633709+00:00 | 2026-10-20T01:30:45.269441+00:00 |

Every preceding verify stage passed, including existing Vitest, SQLite, build, board/focus/autosave, sync/security/credentials, composer, date/language, relationships, feedback, review, period and ordering coverage. The main insight journey passed before its empty-card layout subprocess stopped. The final insight-generation stage had not run. This is not a complete local verify pass.

The empty-card evidence recorded a pointer at the Japanese return control (851.22, 134), followed by a pointerout at (661.27, 570.53) while the script was reading the hint rather than moving the pointer. The native window was visible and unfocused; renderer focus was reported separately. No timeout, refocus loop or product behavior was changed to conceal this result.

Earlier feature-level title Tab/Shift+Tab, completed layout, virtual rows, inline creation, typecheck/build and all 339 existing tests passed. Existing local subtask pointer-drop runs remained unresolved. The release workflow therefore requires full subtask, completed-layout, insight and insight-generation acceptance on its isolated hosted macOS desktop before signing. A local focus observation does not waive those gates.

No optional performance/scaling or manual 100,000-task stress suite was run. Private raw reports and screenshots remain under ignored `apps/desktop/output/tests/release-1.9.9/` and the owning feature output directories. Only synthetic data is used by hosted acceptance.

## Hosted packaging and publication

First hosted attempt: [39354003710](https://github.com/thinkingjimmy/goalloom/actions/runs/39354003710), commit `a61f6b2`. Isolated macOS acceptance passed pointer grouping and existing-title keyboard cases, then an old completed-group assertion read the DOM before its renderer snapshot arrived. Its failure screenshot already showed the reopened group in the main section. The owning scenario now waits for that actual DOM condition within its existing timeout; no product behavior or global timeout changed. The first attempt did not produce a publishable macOS package.

Second candidate: [39354468426](https://github.com/thinkingjimmy/goalloom/actions/runs/39354468426), commit `0868c1c`. All 20 subtask checks and 10 completed-layout checks passed on the isolated desktop. Insight then exposed a runner precondition mismatch: its requested 1440-by-900 content window was clamped to 1024 by 681, clipping an expected breakpoint. The release now prepares and verifies a supported session-scoped native display before both source interaction and packaged acceptance. Unsupported displays fail before tests; no browser viewport is emulated. The mistakenly queued stale candidate [39354402734](https://github.com/thinkingjimmy/goalloom/actions/runs/39354402734) was cancelled and is retained in timing evidence.

Final candidate: [39355324416](https://github.com/thinkingjimmy/goalloom/actions/runs/39355324416), commit `877451b8c318bc8bc5efa3cdc3b6b1660d9e24fd`. The native display changed from 1024 by 768 to 1920 by 1080. Isolated acceptance passed all 20 subtask checks, 35 transaction checks, 10 completed-layout checks, 35 empty-card measurements, the insight/weekly-review journeys and 25 generation checks in each of development and production modes. Hosted scope: macOS 15 / Darwin 24.6.0, Apple M1 virtual CPU, arm64; Electron 44.4.4, Node 24.21.0, SQLite 3.53.4. These hosted replays complete the interrupted source suites; they do not turn the local `pnpm verify` result into a pass.

The candidate's first packaging attempt received Apple `Accepted` results and validated/stapled app and DMG tickets. Both signatures and Gatekeeper assessments passed. A subsequent `stapler validate` call failed with CloudKit `NSURLErrorDomain -1005` / error 68 after the network connection was lost. Only the failed macOS package job and its downstream draft job were requested again on a fresh runner; successful source acceptance and Windows results are reused. The Apple gate is not relaxed, and this workflow is not reported as a clean-run benchmark.

Each platform builds production once and validates its commit/version/platform/file hashes before prepared packaging. Both packaged smokes, app/DMG signing and notarization, Gatekeeper, stapled tickets and signed Keychain first-use/previous-version restoration passed. Windows acceptance used a GitHub-hosted Windows Server 2025 Datacenter VM (10.0.26100, x64, AMD EPYC 7763), with Electron 44.4.4, Node 24.21.0 and SQLite 3.53.4; it does not replace Windows 11 manual acceptance.
