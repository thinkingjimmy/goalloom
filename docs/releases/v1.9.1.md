# Goalloom 1.9.1

## Fixes

- **Sync continues past duplicate goal links.** A duplicate link now rejects only its own operation, keeps the existing link, and lets later changes sync. Other business conflicts remain visible. You do not need to reset sync.
- **Unused sync waits before accessing the keychain.** Starting the app or opening Settings does not request sync keychain access when sync is unused or signed out. Access starts when you choose Google sign-in. Saved signed-in sessions and AI provider keys still restore as before.
- Existing encrypted sync vaults are read once and converted safely. Signing out keeps the encrypted device and account keys for later use.

## Upgrade

Update from 1.9.0 through Settings → About, or install over the existing app. Your workspace and settings stay in place. The workspace format remains v10. macOS downloads are Developer ID signed and notarized by Apple; Windows installers remain unsigned.

**If you still use the published macOS 1.8.0 build, upgrade manually once:** quit Goalloom, open the 1.9.1 DMG, and replace Goalloom in Applications. That old ad-hoc signature cannot authorize the Developer ID update. Your workspace and settings stay in place.

## 修复

- **重复目标关联不再阻断同步。** 现在只拒绝重复关联所在的操作，保留已有关系，后续改动可以继续同步。其他业务冲突仍会显示，无需重置同步。
- **未使用的同步按需访问钥匙串。** 未启用同步或已退出登录时，启动应用、打开设置不再请求同步钥匙串权限。选择 Google 登录后才开始访问。已登录会话和已保存的 AI 服务 Key 仍正常恢复。
- 旧格式的加密同步凭据会读取一次并安全转换。退出登录仍保留加密的设备与账号密钥，供以后重新登录使用。

## 升级

1.9.0 用户可在「设置 → 关于」更新，或覆盖安装，工作区和设置会保留。工作区格式保持 v10。macOS 安装包已通过 Developer ID 签名和 Apple 公证；Windows 安装包仍未签名。

**仍使用公开版 macOS 1.8.0 时，请手动升级一次：** 退出 Goalloom，打开 1.9.1 的 DMG，把 Goalloom 拖进「应用程序」并替换旧版。旧版的 ad-hoc 签名无法通过内置更新切换到 Developer ID 签名，工作区和设置会保留。
