## Delivery and authority

- Electron, Hugeicons, offline desktop, one current placement, independent item states and history / rollover are fixed. A current column never retains a reference card after an item moves elsewhere. Post-setup calendar editing and SVG lines are optional follow-ups, not M4 or launch requirements; initial calendar configuration remains in scope.
- D06/D07 were owner-confirmed on 2026-09-23: a multi-parent DAG with no primary parent or weights, rejecting self-links, duplicate active edges and cycles (widened by the owner on 2026-09-24: a new link — `link`, create with a parent or a plan — needs a parent in a strictly longer horizon and never touches Later, and Later items take no flow colour; moves, undo, restore and import keep existing edges); relationships never aggregate progress or cascade state; fixed three-calendar-month cycles anchored no later than workspace today, calculated from the original anchor with month-end clamping. D08/D11 are macOS 14+ Apple Silicon / Windows 11 x64 and owner-only private testing. D09 was widened by the owner on 2026-09-24: the UI ships in Chinese, English, Japanese, Spanish and French, following the system language by default with a device-level override in Settings (stored outside the workspace). New user-visible copy must be added to every locale; Jev prompts and Chinese date parsing stay Chinese-only. Do not silently add deferred features or expand this scope.
- Implement one milestone at a time. Check tasks only after implementation and relevant tests. Report commands, results, Electron / Node / SQLite versions and OS / CPU / VM / physical-machine scope. Documentation, pure tests and browser mocks are not packaged-desktop acceptance.
- Keep domain rules deterministic with an injected clock and revalidate them in the authoritative write transaction. Enforce CSP, narrow IPC, atomic history, import validation, consistent backups and effect-scoped undo. Compare each operation's owned fields and required identity/dependency guards, not the original whole-item version; current versions protect the read-check-write transaction. Preserve unrelated edits, validate graph/order constraints and never roll versions back or rewrite receipts to rebase the stack. An undo returning todo to any expired period gets a persisted current-period hold, regardless of manual/auto policy.
- Require an explicit initial configuration confirmation before item writes; confirmation locks the calendar, not an incidental first task. Keep the established undo membership and feedback behaviour of the implemented code and feature specs. Every successful undo gives visible feedback; undoing creation provides a scoped restoreItem action bound to that deletion and workspace generation. It preserves edited text and is not a general redo stack. Allow archived relationship endpoints without unarchiving them, and never automatically archive or delete backlog.
- On a definitive undo conflict, change no business data, explain and remove only that session entry; the next keypress handles the next one. Keep original history and do not mark it undone. Transient failures / unknown outcomes retain the entry until the receipt is checked. Unrelated text edits and increasing versions alone do not invalidate undo; creation/deletion still require safe lifecycle and dependency checks.
- Distinguish `restoreItem` (还原), `restoreWorkspace` (备份/JSON恢复), and `resetWorkspace` (重置). Only backup/JSON restore sets `rollover_paused_after_restore`; item undelete leaves that flag unchanged. Reset enters maintenance when protective backup preparation starts: drain accepted writes, block new mutations/reconcile through final confirmation or cancellation, and require a verified backup plus an unchecked-by-default acknowledgement before atomic replacement. Preserve the old runtime state on cancel/failure. Both workspace replacements invalidate old-generation writes, caches and session undo/Toasts, preserve backups and fail without losing old data.
- Use Hugeicons for all UI icons including shadcn internals, explicit imports and accessible controls; no second icon library, remote loading or unapproved Pro dependency. Keep tasks, history, screenshots and backups private; no body telemetry, public release, license change, purchase or DNS action without authorization.
- Read the latest branch before writing, preserve concurrent edits, use non-forced updates and keep the repository Private. Preserve app identity and user-data paths across upgrades.
- GitHub Actions is manual-only (no paid minutes). Before merging into `main`, run `pnpm verify` locally on macOS and report its result; Windows 11 acceptance is the owner's manual step on a Windows machine or VM.

## Project documentation convention

Within this repository, the following project-specific convention replaces personal global documentation defaults where project-level exceptions are permitted. This exception covers README placement, module-header templates and file-size/count preferences only; it never overrides higher-priority safety, permissions or mandatory organizational rules. Read any actually loaded global instructions before implementation. If they prohibit such an exception, report the exact conflict for the owner to resolve rather than assuming either rule wins. Do not claim an unseen global CLAUDE.md has been verified.

Add a short README at a meaningful module boundary only when responsibility/dependencies are not clear from the code. Document INPUT (validated inputs/dependencies), OUTPUT (results/side effects/errors), and POS (layer/responsibility) at complex module entry points, updating these contracts with code. Avoid boilerplate for trivial components, generated shadcn code, assets and lockfiles. Around 800 hand-written lines is a decomposition-review signal, not a hard cap; there is no mandatory eight-file directory limit.

For Claude Code, the repository's one-line [CLAUDE.md](CLAUDE.md) imports this file. Confirm the project instructions were actually loaded rather than assuming AGENTS.md is discovered automatically. See the [official memory documentation](https://code.claude.com/docs/en/memory#agentsmd).
